# /setup — Configure AI-DLC Per-Project Settings

Usage: `/setup [reconfigure | view]`

**Arguments:** $ARGUMENTS

---

## Purpose

Creates or updates `.ai-dlc.local.yaml` in the project root — per-project configuration for AI-DLC skills. Auto-detects the project stack and writes sensible defaults. This file should be committed to the repo so all team members share the same skill configuration.

> Inspired by compound engineering's `setup` skill. One command to configure all skills for your project.

---

## Instructions for Claude

### Step 1: Check Existing Config

```bash
ls .ai-dlc.local.yaml 2>/dev/null
```

**If found:**
- Read and display current settings
- If $ARGUMENTS is `view`: display and stop
- If $ARGUMENTS is `reconfigure`: proceed to Step 2
- Otherwise: ask "Settings file exists. Reconfigure, view, or cancel?"

**If not found:** Proceed to Step 2.

---

### Step 2: Auto-Detect Project Stack

```bash
# Detect language/framework
test -f Gemfile && test -f config/routes.rb && echo "rails" || \
test -f Gemfile && echo "ruby" || \
test -f pyproject.toml && echo "python" || \
test -f requirements.txt && echo "python" || \
test -f tsconfig.json && echo "typescript" || \
test -f package.json && echo "javascript" || \
test -f go.mod && echo "go" || \
test -f Cargo.toml && echo "rust" || \
test -f template.yaml && echo "serverless" || \
echo "general"

# Detect infrastructure
ls Dockerfile docker-compose.yml 2>/dev/null        # containers
ls template.yaml serverless.yml 2>/dev/null          # serverless
ls terraform/ *.tf 2>/dev/null                       # terraform
ls .github/workflows/ 2>/dev/null                    # CI/CD

# Detect existing AI-DLC structure
ls docs/pm/ 2>/dev/null                              # PM framework
ls docs/security/ docs/reviews/ 2>/dev/null          # Security reviews
ls docs/captains_log/ 2>/dev/null                    # Captain's logs
ls docs/solutions/ 2>/dev/null                       # Solution docs
ls docs/brainstorms/ 2>/dev/null                     # Brainstorm docs
```

Announce: "Detected [type] project with [features]. Let me configure your settings."

---

### Step 3: Ask Configuration Method

Ask: "Auto-configure with smart defaults, or customize?"

**Option A: Auto-configure (recommended)**
- Use detected stack to set all defaults
- Write the file immediately
- Show what was written

**Option B: Customize**
- Walk through each section interactively

---

### Step 4: Build Configuration

If customizing, ask these questions one at a time:

**4a. Review focus areas** (multi-select):
- Security (OWASP, auth, secrets)
- Performance (N+1, caching, optimization)
- Architecture (coupling, boundaries, patterns)
- Simplification (YAGNI, dead code, over-engineering)
- Operations (monitoring, alerting, deployment)

**4b. Test configuration:**
- What's your test command? (auto-detected or custom)
- Target coverage? (default: 80%)

**4c. Health check thresholds:**
- Context freshness: how many days before CLAUDE.md is stale? (default: 30)
- Security review: how many days between reviews? (default: 30)
- Backlog grooming: how many days before stale? (default: 7)

---

### Step 5: Write the Config File

Write `.ai-dlc.local.yaml`:

```yaml
# AI-DLC Per-Project Configuration
# Generated by /setup on YYYY-MM-DD
# Commit this file — it configures AI-DLC skills for all team members.

project:
  name: [from CLAUDE.md or directory name]
  type: [detected type]
  stack: [detected stack details]

review:
  # Focus areas for /five-persona-review and /staff-panel
  focus_areas:
    - security
    - architecture
    - simplification
  # Extra context passed to all review personas
  extra_context: ""
  # Personas to skip (if any)
  skip_personas: []

testing:
  # Override auto-detected test runner
  command: [auto-detected or custom]
  target_coverage: 80

health:
  # Thresholds for /motherhen checks (in days)
  context_freshness: 30
  security_review: 30
  backlog_grooming: 7
  foundation_docs: 60

# Environment variables for portable skills
env:
  # Uncomment and set if using ticky for Azure DevOps
  # TICKY_HOME: ~/repos/ticky
  # Uncomment and set for prodstatus
  # CALLHERO_HOME: ~/repos/callhero
  # Uncomment and set for webteam
  # SITE_URL: https://example.com

# Knowledge compounding
solutions:
  # Directory for solution documents
  path: docs/solutions
  # Auto-suggest documenting after problem resolution
  auto_suggest: true

brainstorms:
  # Directory for brainstorm documents
  path: docs/brainstorms
  # How many days before a brainstorm is considered stale
  freshness_days: 14
```

---

### Step 6: Verify and Report

After writing:

1. Display the full config
2. Check if `.ai-dlc.local.yaml` is in `.gitignore` — it should NOT be (this is shared config, not secrets)
3. Suggest: "Commit this file so your team shares the same configuration."
4. Offer to run `/motherhen` to verify project health with the new config

---

## Integration

This config file is read by:
- `/motherhen` — uses `health.*` thresholds instead of defaults
- `/dlc-audit` — uses `testing.*` configuration
- `/five-persona-review` — uses `review.*` settings
- `/staff-panel` — reads `review.extra_context` for project context
- `/bolt-lfg` — uses `brainstorms.*` and `solutions.*` paths
- `/pm plan` — uses `brainstorms.freshness_days` for document discovery
